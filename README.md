# SNUWCANVAS

Windows 네이티브 C++20 클라이언트입니다. Python/Tkinter/PyInstaller를 실행하지 않습니다.
이미지 캔버스와 패널은 Direct2D, 글자는 DirectWrite, 통신은 WinHTTP를 사용합니다.
텍스트 편집·파일 선택은 Windows 기본 컨트롤을 사용합니다.

작업 공간 루트의 `SNUWCANVAS.exe` 하나를 실행·배포합니다. 별도 EXE 사본이나 ZIP은 생성하지 않습니다.
서버와 ComfyUI의 Python 환경 및 API는 기존대로 유지됩니다.

## 사용

처음 실행할 때 로그인하지 않았다면 시작 메뉴만 표시됩니다. **로그인 / 계정 만들기**로 인증한 뒤 작업 공간을 사용합니다. **내 계정** 페이지에서 프로필 편집·로그아웃·모든 기기 로그아웃을 사용하며, 로그아웃하면 시작 메뉴로 돌아갑니다. 서버 주소는 내부 설정을 사용하며 로그인 화면과 전체 설정에 노출하지 않습니다.
서버에서 계정 인증을 활성화해야 로그인할 수 있습니다. HTTP 401은 인증 거부이며 WinHTTP 12029는 연결 실패입니다.

- 프로젝트는 왼쪽에서 선택하고, 새로 만들기·저장·관리는 같은 사이드바에서 합니다.
- 왼쪽 세로 아이콘을 클릭하면 페이지가 전환됩니다. 아이콘 위에 잠시 마우스를 놓으면 설명이 표시됩니다. 맨 위 아이콘으로 프로젝트 목록을 열고 닫습니다. 일관성·학습은 develop 계정에만 표시되며 일반 계정은 서버 API에서도 거절됩니다.
- 사이드바 하단에는 커뮤니티·저장·프로젝트 관리·전체 설정·내 계정 아이콘이 있습니다. 내 계정 페이지에서 이메일·권한·사용량을 확인하고 닉네임·자기소개를 저장합니다. 회원가입에는 닉네임이 필요하며 같은 이메일로 여러 계정을 만들 수 없습니다.
- 생성 화면의 편집 패널은 기본 최대 380px로 제한하고 나머지는 이미지 작업 공간으로 사용합니다. 프롬프트·제외할 내용은 짧은 편집창에서 스크롤하며, 고급 설정은 별도 탭에 있습니다. 다른 설정 화면은 520px 패널을 사용합니다. 패널 경계를 직접 끌어 폭을 조절할 수도 있습니다.
- 이미지 작업 공간 위쪽의 **갤러리 / 미리보기**로 전체 그리드와 큰 단일 이미지를 전환합니다. 저장·폴더·확대·URL은 하단 도구 모음에 있습니다.
- 프로젝트를 드래그하면 순서가 바뀝니다. 폴더 헤더에 놓으면 폴더로 이동합니다. 왼쪽 상단 ▱+ 또는 우클릭 → 새 폴더로 정리하며, 폴더 클릭은 접기/펼치기입니다.
- 폴더 우클릭으로 이름 변경·폴더 해제가 가능하며, 프로젝트 우클릭 → 폴더로 이동도 지원합니다. 목록 끝의 폴더 밖으로 이동 영역에 놓으면 루트로 이동합니다.
- 생성 모델·스타일·품질은 중앙 하단에서 선택합니다. 생성 중 다시 누르면 예약합니다.
- 이미지 라이브러리는 휠, 빈 영역/썸네일 위 드래그, 오른쪽 스크롤 손잡이로 이동합니다. 패널 폭을 늘리면 이미지 열 수와 목록 높이가 함께 늘어납니다. 최근 썸네일은 256개까지 캐시합니다.
- 썸네일을 클릭하면 미리보기, 더블클릭 또는 자세히 보기는 Windows 기본 이미지 앱입니다.
- 프롬프트의 쉼표 단위 태그에 커서를 놓고 Ctrl+↑/↓로 가중치를 0.1씩 조절합니다. 우클릭 메뉴에서 조절·초기화할 수 있습니다.
- 메인 창은 Windows 기본 상단 바를 사용합니다.
- 시작 로딩 창은 고정 크기·타이틀바 없는 별도 창이며 실제 초기화가 끝나면 닫힙니다.
- Ctrl+S 저장, Ctrl+N 새 프로젝트, Ctrl+O 프로젝트 파일 열기.

## 데이터

EXE 옆 `data/config`, `data/prompts`, `data/generated`를 사용합니다.
기존 JSON 형식을 읽고 저장하며, 별도 출력 폴더와 참조 이미지 경로는 유지합니다.
기존 `config`와 `prompts`만 있고 `data/config`가 없는 경우 최초 실행에 복사하여 가져옵니다.
프로젝트 삭제는 이미지 파일을 삭제하지 않습니다.

## 소스와 빌드

클라이언트 소스: `src/native/` (이전 Python 클라이언트 소스는 제거했습니다.)
서버는 별도 저장소로 관리합니다. 빌드는 같은 작업 공간의 서버 버전·동의서·모델 설정을 포함합니다.

빌드 도구: MSYS2 UCRT64 MinGW-w64 g++ / windres.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build_native.ps1 -Publish
```

창을 띄우지 않는 정적 배포 검증: `python tools/verify_exe_icon.py`
로컬 API 호환성 검사: `python tools/test_native_api.py` (테스트 서버만 사용, GUI 없음).
네이티브 `--self-test`, `--graphics-test`, `--migration-test`, `--api-test`는 창을 만들지 않습니다.

[네이티브 전환 안내](docs/native-client.md) · [모델과 보정](docs/model_workflows.md) · [편집](docs/editing.md)

폴더 구성과 보존 기준: [작업 공간 안내](docs/workspace.md).

빌드는 작업 공간 루트 `SNUWCANVAS.exe` 하나를 갱신합니다. 앱 실행 데이터 경로는 변경하지 않습니다.

서버 변경이 함께 필요한 경우 서버 저장소의 소스도 Git으로 갱신하고 재시작합니다.
클라이언트 빌드로 서버 ZIP을 만들거나 운영 서버의 설정·데이터를 덮어쓰지 않습니다.

## 독립 저장소와 검사

이 폴더 자체를 Git 저장소 루트로 사용합니다. `assets`, `src`, `tools`, `tests`, `docs`를 함께 올립니다.
실제 설정·키·프로젝트·생성 이미지·빌드 결과는 .gitignore로 제외합니다.
`python -m pip install -r requirements-dev.txt` 후 빌드하고 `python -m unittest discover -s tests -v`로 검사합니다.
일반 빌드는 작업 공간 루트의 `SNUWCANVAS.exe`도 갱신합니다. 실행 중이면 앱을 종료한 뒤 다시 빌드하세요.
`-Publish`는 이전 명령과 호환되도록 허용하지만 ZIP이나 EXE 사본을 만들지 않습니다. 테스트도 루트 EXE를 사용합니다.
컴파일 결과는 `.build/SNUWCANVAS.next.exe`에 잠시 쓴 뒤 성공 시 루트 EXE를 교체합니다. 설정·이미지·DB는 복사하거나 삭제하지 않습니다.

커뮤니티는 왼쪽 아래 **커뮤니티** 버튼으로 설정된 서버의 `/community/`를 브라우저에서 엽니다. 서버에서 `ACCOUNT_AUTH_ENABLED=1`, `COMMUNITY_ENABLED=1` 설정과 `community` 프런트엔드 빌드가 필요하며 웹에서 다시 로그인합니다.
각 생성 작업은 기본 2시간의 전체 제한 시간이 있으며 설정 JSON의 `job_timeout_seconds`로 조절할 수 있습니다.
중지 시 로컬 대기열과 통신을 취소하고 서버 취소 확인 결과를 표시합니다. 서버 연결이 끊기면 원격 중지는 확인할 수 없습니다.

## 상태 알림과 다운로드 변경

클라이언트는 /jobs/{id}/events 연결 하나로 상태 변경 알림을 받으며 상태 GET을 반복하지 않습니다.
서버와 클라이언트를 함께 업데이트해야 합니다. 연결이 끊기면 오류를 표시하고 자동 반복 조회는 하지 않습니다.
서버는 출력 경로가 ComfyUI와 다르면 소유권을 확인한 작업 결과를 ComfyUI /view에서 가져옵니다.

## 일관성 / 성과 학습 / 서버 이미지

일관성의 **학습 이미지**에서는 한 번에 최대 100장을 선택해 추가하고, 전체 이미지 목록을 스크롤해서 확인합니다.
썸네일을 누르면 크게 미리보고, 체크박스와 전체 선택으로 고른 이미지를 **선택 삭제**할 수 있습니다.
추가 장수와 진행 상태를 표시하며, 학습 중인 자료는 학습 중지 후 삭제합니다. 학습 환경·계정 허용·모델 불일치 상태를 구분합니다.
이 기능은 서버 소스도 함께 업데이트해야 합니다. 기존 계정·프로필·이미지는 유지합니다.

- 일관성: 캐릭터·제품·브랜드·스타일 프로필 등록, 참조 업로드, 생성 적용, LoRA 학습/상태/중지.
- 성과 학습: 선택 이미지 또는 예시 파일 평가, 시각 분석, 게시물별 노출/클릭/좋아요 입력, 다음 생성에 학습 반영.
- 서버 이미지: 현재 채널/API 키 전체 목록을 200개씩 이전/다음 페이지로 이동하며을 사용자가 갱신하고 선택 파일을 가져와 미리보기.
- 자연어편집의 모델 새로고침 후 서버에 설치된 Ollama 모델을 선택합니다.

프로젝트 이름/ID를 채널 정보로 서버에 전달합니다. 비밀키는 기존대로 로컬 메타데이터에서 제외합니다.
생성 상태는 기존 단일 이벤트 연결을 사용하며 새 기능도 주기적인 상태 조회를 시작하지 않습니다.
학습/이미지 분석 상태는 버튼을 누를 때 한 번 조회합니다. 긴 작업 중에는 다른 이미지 생성이 기다릴 수 있습니다.
서버 소스도 함께 업데이트해야 하며 실제 LoRA 학습은 서버 관리자가 격리된 GPU 학습 환경을 설치해야 합니다.

## 학습 화면 레이아웃

일관성은 `생성에 적용 / 프로필 등록 / 참조·학습`, 성과 학습은 `이미지 평가 / 게시물 성과 / 학습 결과`로 나눴습니다.
버튼은 관련 입력 바로 아래에 배치하고, 평가 대상 파일 선택은 선택 이미지 안내 옆에 배치했습니다.
프로필 등록이 완료되면 참조·학습 화면으로 이동합니다. 목록에서는 긴 식별자 대신 프로필 이름을 보여줍니다.
창 크기와 패널 폭을 바꾸면 입력/버튼 위치와 스크롤 범위를 함께 다시 계산합니다.
생성 API, 평가/학습 요청 및 기존 저장 형식은 유지합니다.

일관성 화면은 사용하기 / 새로 등록 / 이미지·학습으로 구성됩니다. 등록 이미지 수와 학습까지 필요한 수, 이미지별 설명(최대 4개 요약)을 함께 표시합니다. 업로드 후 한 번 목록을 갱신하며 반복 상태 조회는 하지 않습니다. 설명은 여러 줄로 입력하고 Ctrl+A로 전체 선택할 수 있습니다. 자동 캡션은 다음 기능으로 준비 중이며 아직 실행되지 않습니다.

### 독립 캡션 API 테스트

일관성 → 자동 캡션에서 캡션 API 주소(`http://서버의-Tailscale-IP:8010`)와 `config/caption.env`의 `CAPTION_API_KEY`를 입력합니다. 이미지 생성 서버 키와 별도로 입력하세요. 모델 조회 → 비전 모델 선택 → 이미지 선택 → 자동 캡션 순서입니다. 결과는 수정할 수 있고, 이미지 설명에 적용하면 같은 파일을 참조 등록에 사용할 수 있습니다. 실제 등록은 이미지 추가를 눌러야 합니다.

Ubuntu의 캡션 서비스는 `config/caption.env`에서 `CAPTION_HOST=0.0.0.0` 또는 서버 Tailscale IP로 설정한 뒤 `bash run.sh`로 재시작해야 다른 PC에서 접근할 수 있습니다. API 키는 기존 생성 서버로 보내지 않고, 프로젝트 내보내기와 이미지 메타데이터에서도 제외합니다. 요청 중지는 클라이언트의 대기를 취소합니다. Ollama에서 이미 시작된 GPU 연산의 즉시 종료는 보장하지 않습니다.

자동 캡션의 생성용 모드는 상세 긍정·부정 프롬프트를 각각 표시합니다. 학습용 모드는 부정 문구를 만들지 않습니다. 대상 생성 모델 계열은 현재 생성 모델 선택을 기준으로 보내며, 이미지 설명 적용에는 긍정 결과만 사용합니다.

캡션 API 0.3.0부터 응답 버전과 태그 수를 표시하고, 구버전 API에 대한 업데이트 안내를 제공합니다. 캡션 요청 제한 시간은 600초이며, 짧은 결과의 세부 보완은 API에서 최대 한 번 수행합니다.

## 전체설정과 모드

왼쪽 아래 **전체설정**에서 생성 서버 주소/API 키와 캡션 서버 주소/전용 키를 한 번 설정합니다. 채널을 바꿔도 이 값은 유지하며 프로젝트 데이터에는 전역 비밀 키를 복제하지 않습니다. 생성 장수·크기·모델 등 작업별 설정은 기존 생성 설정에 남습니다.

STANDARD MODE는 기존 다크 디자인, HARDCORE MODE는 기본 배경·글자 색상을 유지하고 박스 테두리만 차분한 붉은색으로 강조합니다. 하드코어 전환에는 fr- 관리 키가 필요하고 실제 허용 여부는 서버가 다시 확인합니다. 이미지 원본은 색상을 바꾸지 않습니다. 이미 하드코어 모드로 저장한 것으로 표시된 로컬 생성 이미지는 일반 모드 라이브러리에서 숨깁니다. 외부에서 가져온 임의의 로컬 파일까지 검증했다는 뜻은 아닙니다.

전체설정의 **스플래시 최소 2초**를 켜면 준비가 빨라도 최소 2초 표시합니다. 끄면 준비 즉시 닫습니다. 시작 애니메이션은 이번 업데이트에 포함하지 않았습니다.

전체설정의 하드코어 버튼 하나로 현재 상태 확인과 켜기/끄기를 합니다. 안전 모드 전환 시 입력 컨트롤을 만들기 전에 테마 속성을 갱신하여 이전 모드의 붉은 테두리가 남지 않도록 합니다.

## 배포판 생성 기본값

새 설치 기본값은 현재 사용자의 SDXL 작업 설정에 맞춘 832×1216, 26 steps, CFG 5, euler_ancestral / normal, denoise 1, 무작위 seed, 1장입니다. Hires와 Ollama 프롬프트 보정은 기본 OFF로 두어 추가 패스와 모델 교체 비용을 줄입니다. Hires를 수동으로 켤 때 기본값은 1.5배, 추가 10 steps, denoise 0.35입니다. 기존 설정 파일과 프로젝트는 덮어쓰지 않습니다. 배포 EXE에는 개인 키·프로젝트를 포함하지 않으며 기본 서버 주소만 내장합니다.

SDXL 속도 프리셋은 빠르게 20 / 균형 26 / 고품질 32 steps이며 고품질만 Hires를 켭니다. FLUX 전용 steps·CFG·샘플러 규칙은 별도로 유지합니다. 이는 배포판의 시작 설정이며 모든 체크포인트의 최적값을 보장하지 않습니다. 실제 GPU 속도·화질 비교는 운영 모델에서 확인해야 합니다.

여러 장 생성 시 한 장의 완료 알림을 즉시 받아 해당 이미지를 저장·표시하고 다음 알림을 처리합니다. 전체 배치 완료를 기다리지 않습니다. 상태 알림은 연결 하나를 유지하며 반복 조회하지 않습니다.

## 2.0 Phase 1 개발 빌드

형제 server/version.json과 server/legal/consent-<version>.md에서 앱 버전/동의 리소스를 생성합니다. 첫 실행에 필수 개발용 동의 화면과 선택 하드웨어 동의를 표시하며, 설치별 UUIDv4와 동의 기록은 Windows 현재 사용자 DPAPI로 보호합니다. 다른 Windows 사용자로 암호화된 ID를 복사하면 자동으로 초기화하지 않고 오류를 표시합니다.

모든 HTTP 요청에 X-Client-Version을 붙이고 정상 앱 실행에는 X-Client-Id도 전송합니다. 서버 설정이 있으면 앱 초기 연결 및 이후 API 사용 전에 버전/동의 문서를 확인하고 등록합니다. 동의가 바뀌면 다시 동의해야 합니다. 서버 연결·등록 실패 시 해당 기능을 사용할 수 없으며, 초기 연결 실패는 시작 오류로 표시됩니다. 계정 로그인 UI와 자동 업데이트는 후속 Phase 범위입니다.

`--foundation-test`, `--foundation-network-test`는 임시 폴더/모의 서버에서만 쓰는 GUI 없는 개발 검사 모드입니다. 개인정보 초안은 법률 검토를 받은 문서가 아니므로 서비스 공개 전 전문가 검토 필요. 실제 설치 EXE는 교체하지 않았습니다.

### Phase 3 개발 변경

생성 카드에 사용한도·잔여량·기한과 게이지를 표시합니다. 시작 시/연결 확인/작업 상태에서 갱신하며 서버가 최종 판정합니다. 개발자 키도 서버 확인 후 모드 전환할 수 있습니다. 설치된 EXE/ZIP은 교체하지 않았습니다.
