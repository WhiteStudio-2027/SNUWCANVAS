# 프로젝트 정리와 썸네일 수정

## 사용

- 프로젝트 행을 드래그하면 위/아래 삽입 위치가 표시됩니다. 놓으면 순서가 저장됩니다.
- 왼쪽 상단 `▱+`, 목록 우클릭, 또는 관리 메뉴의 새 폴더로 폴더를 만듭니다.
- 프로젝트를 폴더 헤더에 놓으면 해당 폴더로 이동하고 펼쳐집니다.
- 폴더를 클릭하면 접기/펼치기, 폴더 헤더를 드래그하면 폴더끼리 순서를 바꿉니다.
- 폴더 우클릭으로 이름 변경·폴더 해제가 가능합니다. 폴더 해제는 프로젝트를 루트로 옮기며 삭제하지 않습니다.
- 프로젝트 우클릭의 폴더로 이동 메뉴 또는 드래그 중 목록 끝의 폴더 밖으로 이동 영역으로 루트에 옮깁니다.
- 긴 프로젝트 목록은 휠로 스크롤합니다. 드래그 중 목록 위/아래 가장자리에서 자동으로 스크롤합니다.
- 검색 중에도 폴더 안 프로젝트를 찾을 수 있습니다.

폴더는 앱 안의 프로젝트 분류입니다. 이미지 파일이나 출력 경로는 이동하지 않습니다. 폴더·소속·수동 순서·접힘 상태는 기존 channels.json의 추가 필드로 보존하며 프로젝트 ID, 프롬프트와 설정은 그대로 유지합니다.

## 이미지 문제

이전 캐시는 파일명 순으로 가장 앞에 있는 썸네일을 제거했습니다. 캐시 64개가 가득 찬 뒤 이름이 더 앞서는 이전 이미지를 읽으면, 새로 읽은 썸네일들이 서로 제거되어 같은 페이지가 계속 로딩됐습니다. 파일명과 무관하게 마지막 사용 시각으로 제거하는 LRU 캐시로 교체했습니다. 캐시 크기는 64개로 유지합니다.

## 변경 위치

- client/src/native/project_organizer.hpp: 폴더·프로젝트 순서·이동·검색 행 구성.
- client/src/native/model.hpp: 기존 프로젝트에 폴더 필드를 선택적으로 저장하고 새 프로젝트의 소속을 유지.
- client/src/native/app.hpp, app.cpp: 폴더 버튼·메뉴·접기·드래그 삽입 표시·목록 스크롤.
- client/src/native/thumbnail_cache.hpp: 파일명에 영향받지 않는 LRU 캐시.
- client/src/native/main.cpp: 프로젝트 목록 휠 전달, 창 없는 새 검사 진입점.
- client/src/native/runtime_tests.hpp, client/tests/test_native_client.py: 정렬·폴더·재시작 복원·손실 없는 폴더 해제 및 가득 찬 썸네일 캐시의 이전 10페이지 검사.

대화형 앱 창은 검사를 위해 실행하지 않습니다.

## 빈 썸네일 회귀 수정

LRU 캐시의 find에서 저장된 ComPtr의 주소를 `&`로 가져온 것이 직접 원인이었습니다. WRL ComPtr는 이 연산자를 출력 인자용으로 오버로드하고, ComPtr 포인터로 변환될 때 기존 이미지 참조를 해제합니다. 조회에는 std::addressof를 사용하도록 수정했습니다.

이전 정수 값 캐시 검사만으로는 이 회귀를 검출하지 못했습니다. 새 library_render_test.hpp 검사는 테스트 전용 창을 만들지 않고 실제 App::paint와 tick, 이미지 작업자, 이미지 업로드 및 캐시를 GPU 렌더 대상에 연결합니다. 수정 전 9칸 모두 빈 GPU 픽셀(0/9)로 실패했고, 수정 후 100%·150%·200%에서 45페이지의 썸네일 픽셀 확인을 통과했습니다. 전체 메인 클라이언트 검사 8개도 통과했습니다.

graphics.hpp의 렌더 대상은 공통 Direct2D 인터페이스와 Windows 창 대상을 분리하여, 실제 화면 코드를 창 없이 검사할 수 있게 했습니다. 대화형 창 이동·마우스 조작의 육안 검사는 수행하지 않았습니다.
