# 실행 중 로컬 빌드 업데이트 — 0.3v

처음 한 번은 새 `SNUWCANVAS.exe`로 재실행해야 합니다. 이후에는 앱을 켜둔 채 기존 `tools/build_native.ps1`로 빌드하면 됩니다.

1. 빌드 도구가 새 EXE를 별도로 저장하고 SHA-256·크기·버전 정보를 게시합니다.
2. 앱이 2초 간격으로 새 빌드를 감지하고 별도 작업자에서 검증합니다.
3. 생성·학습·파일 작업·한글 입력이 끝나고 3초간 입력이 없으면 현재 입력과 설정을 저장합니다.
4. 별도 도우미가 이전 프로세스의 정상 종료를 기다린 뒤 새 앱을 시작합니다.
5. 새 앱이 준비 완료를 알리지 못하고 종료되면 이전 실행 파일로 복구합니다. 실행 중인 앱을 강제 종료하지 않습니다.

바로 확인하려면 `전체 설정 → 새 빌드 적용`을 누릅니다. 작업이 진행 중이면 적용을 보류합니다. 실행 파일이 잠겨도 빌드 결과를 대기시키며 사용자 앱을 종료시키지 않습니다.

업데이트 파일·백업·상태 기록은 EXE 옆의 숨김 폴더 `.updates/local/`에 저장합니다. 계정·프롬프트·생성 이미지는 이 폴더에 복사하지 않습니다. 오류는 `<실행 파일 이름>.status.json`에서 확인할 수 있습니다. 서버의 원격 서명 업데이트와 로컬 빌드 업데이트는 별도로 검증합니다.

제품 표시는 서버·클라이언트 모두 `0.3v`, 내부 버전은 `v0.3.0`, 배포 세대는 `2`입니다. 세대 정보가 없는 과거 `v3.5` 원격 배포본은 새 업데이트로 적용하지 않습니다. 과거 버전의 복구 기록도 새 세대의 시작 과정에 적용하지 않습니다.

기존 서버의 최소 클라이언트 버전이 `v2.0.0` 이상이면 새 `v0.3.0` 클라이언트가 거절될 수 있습니다. 서버도 함께 업데이트해야 합니다. `server/dist/SNUWCANVAS_server_update.zip`은 설정·계정·생성 이미지를 포함하지 않는 서버 소스 업데이트입니다. 서버를 중지하고 설치 폴더에서 기존 `update.sh`로 적용한 후 다시 실행합니다.

안정성 보강:
- 복구는 적용 직전에 실제로 잰 이전 빌드 해시와 백업으로 합니다. 복구가 실패하면 상태가 `rollback_failed`(종료 코드 3)로 남고 `.updates/local/apply.log`에 기록합니다.
- 새 앱이 아직 실행 중이면(준비 완료 미확인) 이전 앱을 다시 띄우거나 복구하지 않고 `health_unconfirmed`로 남깁니다. 이 상태는 새 앱이 다음 시작 때 `healthy`로 바꿉니다. 상태 파일 읽기는 재시도합니다.
- 빌드마다 `build_id`를 부여합니다. 실패한 빌드는 같은 `build_id`로는 재시도하지 않고, 다시 빌드하면 자동으로 재시도합니다. `새 빌드 적용`은 실패 기록과 무관하게 다시 시도합니다.
- 빌드 도구는 대상별 `.stage.lock`으로 동시 게시를 막고, 대기 파일 이름을 빌드마다 다르게 씁니다. 잠금 판정은 실행 중 프로세스 또는 공유 위반일 때만 하고, 그 외 실패는 대기시키지 않고 중단하며 현재 EXE를 점검·복구합니다. 최근 3개를 넘은 대기 빌드와 도우미 사본은 정리합니다.
- 저장 실패나 도우미 실행 실패는 상태줄에 표시하고 10초간 재시도하지 않습니다.
- 서명: 빌드 도구가 설명 파일(schema 2)을 로컬 키로 서명하고, 앱은 내장된 공개키(`local-build-public.der`)로 검증한 payload만 신뢰합니다. 서명이 없거나 틀리거나 키가 내장돼 있지 않으면 적용하지 않습니다(schema 1도 거부). 개인키는 현재 사용자 인증서 저장소(`CurrentUser\My`, 내보내기 불가)에만 있고, 처음 한 번 `tools/new_local_build_key.ps1`로 만듭니다. 키가 없는 PC에서 빌드하면 EXE만 교체하고 실행 중인 앱에는 재시작 신호를 보내지 않습니다.
- 재생 방지: 이미 적용한 빌드(`.updates/local/applied.json`)보다 오래된 `built_at`의 자동 적용은 거부합니다. `새 빌드 적용`으로는 직접 적용할 수 있습니다.
- 첫 서명 빌드는 기존 앱이 schema 2를 거부하므로 앱을 닫은 상태에서 빌드해 EXE를 직접 교체한 뒤 한 번 실행해야 합니다. 키를 새로 만들면(`-Force`) 같은 절차가 다시 필요합니다.
- 한계: 같은 사용자 권한의 프로그램은 EXE를 직접 덮어쓸 수 있으므로, 이 서명은 `.updates` 폴더에만 쓸 수 있는 경우나 다른 계정의 변조를 막는 용도입니다.

검증은 임시 EXE·DB·키·이미지와 숨겨진 테스트 창으로 수행합니다. 사용자 앱 강제 종료, 실제 GPU 생성, 원격 배포는 수행하지 않습니다.
